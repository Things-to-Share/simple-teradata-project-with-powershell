# Documentation: `simple-teradata-project-with-powershell`

## Introduction

This framework is a structured, enterprise-grade solution for deploying and managing Teradata database objects using PowerShell. It is designed for data engineers who need a controlled, repeatable way to manage SQL objects (tables, views, stored procedures) across multiple environments (Development, Test, Acceptance, Production).

The framework covers:

- **Access & Rights management** — environment-specific access configuration and onboarding instructions.
- **AI-assisted documentation** — structured prompts for generating consistent documentation via ASN GPT.
- **Base SQL features** — reusable Teradata components for logging, generic data processing, and metadata management.
- **Deployment automation** — PowerShell-driven comparison, build-file generation, and publishing of SQL changes.
- **Core scripts** — modular PowerShell scripts handling connectivity, SQL parsing, schema comparison, and data processing.

---

## Hierarchical Structure

### Level 1 — Access [`access.md`](./access/access.md)

Describes how to obtain the correct rights for OTA and Production environments, ODBC driver setup, and DSN configuration. Includes an email template for requesting database access.

---

### Level 2 — AI Prompts [`ai_prompts.md`](./ai_prompts/ai_prompts.md)

A library of structured prompts used with ASN GPT to generate standardized documentation. Prompts follow a consistent read → confirm → STOP → generate pattern and cover PowerShell scripts, SQL objects (tables, views, procedures), and folder-level summaries.

---

### Level 3 — Base Features [`base_features.md`](./base_feautes/base_feautes.md)

Three interconnected SQL subsystems providing the foundation for all data operations:

- **Logging** — hierarchical process tracking with duration and error handling.
- **Generic** — reusable procedures for table creation, data loading, SCD2 historization, and dynamic SQL execution.
- **Metadata** — automated dependency detection, impact analysis, and process group management.

**Example — start and finish a logged process:**

```sql
CALL logging_usp_start('MyProcess', 'Description', NULL, '', l_log_id);
CALL generic_usp_load_view_into_table('my_schema', 'my_table', '1=1', 0, l_status);
CALL logging_usp_finish(l_log_id, -1);
```

---

### Level 4 — Deployment [`deploy.md`](./deployment/deploy.md)

The `deploy.ps1` script is the entry point for deploying SQL objects. It delegates to `ps_build_and_publish`, which compares file definitions against the database, generates numbered SQL build files, and optionally executes them. Post-deployment, metadata is refreshed automatically.

**Example:**

```powershell
deploy -ip_cd_environment "T" -ip_publish -ip_excl_drop_objects
```

---

### Level 5 — Scripts [`scripts.md`](./scripts/scripts.md)

A set of five modular PowerShell scripts providing all underlying logic:

| Script | Role |
|---|---|
| `.load_modules.ps1` | Entry point; loads all other scripts |
| `classes.ps1` | In-memory data structures (`cl_table`, `cl_column`) |
| `functions.ps1` | Core logic: connectivity, SQL parsing, schema comparison |
| `build_and_publish.ps1` | Orchestrates build and deployment |
| `process_data.ps1` | Executes data processing pipeline and validates results |

## Key Features

| Feature | Description |
|---|---|
| **Multi-environment support** | Targets O/T/A/P environments via a single parameter |
| **File-to-database comparison** | Compares local SQL definitions against live database state |
| **Safe ALTER generation** | Four-step rename/recreate/copy/drop prevents data loss |
| **SCD2 historization** | Built-in support for Slowly Changing Dimension Type 2 patterns |
| **Comprehensive logging** | Hierarchical process tracking with duration, parent-child relationships, and debug output |
| **Automated metadata management** | Dependency detection, impact analysis, and process group assignment |
| **Retry logic** | Database operations retry up to 3 times with progressive delays |
| **Credential security** | Credentials encrypted and stored locally; never hardcoded |
| **AI-assisted documentation** | Structured prompt library for consistent, reusable documentation generation |
| **Post-deployment validation** | Log table queried after data processing to confirm success |
